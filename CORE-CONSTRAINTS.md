# Core constraints — paths and rules where changes stay human-reviewed

Everything listed here is load-bearing for what the teaching agent IS.
Automated agents may propose changes in discussion, but merges touching
these paths always require the learner's explicit code-owner approval.

## Constraint #1: the KB write path

**`scripts/kb_append.py` is the ONLY write path for knowledge evidence.**
The code and the live knowledge base share this repository, and the teacher
may commit KB changes directly to `main` while dev work uses branches.

- `kb/events.jsonl` is the append-only source of truth. Never hand-edit,
  rewrite, or casually reorder it; every append validates its hash chain.
- `scripts/kb_lib.py`, `scripts/kb_append.py`, `scripts/kb_derive.py`, and
  `scripts/kb_migrate.py` are the guarded evidence boundary.
- `docs/current-state.md` is GENERATED by `kb_derive.py`; never hand-edit it.
- Dev branches must start from a current `origin/main`, keep their changes
  narrowly scoped, and never overwrite concurrent live-KB commits. If a
  branch conflicts with KB movement, stop and reconcile rather than forcing.

## Learning spine and privacy

- Purpose, learning loop, one trusted interface, and "struggle stays in the
  material" change only with explicit learner approval.
- Evidence levels never advance past the observed evidence; delay is a
  separate dimension. Unverified sources stay marked unverified.
- Learner data is private by default. Autonomous behavior defaults off and
  billing/authentication failures pause autonomy.
- Channels are adapters; learning policy and evidence stay in this project.

Guardian files:

- `AGENTS.md`, `docs/thesis.md`, `docs/learner.md`, and `docs/routing.md`
- `docs/proposals/knowledge-storage.md` and `docs/decision-log.md`
- `src/teaching_agent/` — prompts, pedagogy, KB integration, and scheduling

## Deploy safety

- `.github/` — CI, Dependabot, and auto-merge wiring.
- `pyproject.toml` — runtime dependencies and packaging.

## Rule of thumb

If a change can corrupt or bypass the evidence log, collide with live KB
commits, overstate learning, expose private data, or alter the learning
spine, it belongs to a learner-reviewed change.
