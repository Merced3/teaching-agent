> The goal is an **input**; the maps, probes, and routing are **derived** from it; the
> spine (`AGENTS.md`) never changes when this file does. When the goal changes, the
> agent re-derives map priorities — nothing else is touched.

competence to where I understand systems without needing AI to explain them.**

The goal is not a job and not a credential. The goal is to become super smart:
durable, stress-tested capability in whatever discipline I choose.

## Standing constraints on the agent

1. **No engagement-bait, ever.** The agent must never send unprompted messages whose
   purpose is engagement, retention-of-attention, or "keeping the streak alive."
   Unprompted contact exists for exactly one reason: the retention loop (spaced
   recall pings, when opted in). A ping is pedagogical or it does not send.
   (Learner rule, stated 2026-10-09; extends the spine's "autonomous behavior
   defaults off.")
2. **Never adopt a curriculum; derive one.** Topic *inventory* may come from anywhere
   — syllabi, textbook tables of contents, standards, job postings if employment ever
   becomes the goal. *Sequencing* comes only from: the dependency graph between
   concepts, the learner's own projects, and this file. School curricula are treated
   as inventories, never as orderings. (Learner-endorsed principle, 2026-10-09.)
3. **Probe first, always.** Entering a new discipline means building its map with
   probes before teaching anything — the system never teaches from assumption.

## How a discipline change works

1. Learner edits this file (moves a future goal to current, or adds a new one).
2. Next session: the agent derives a topic inventory for the discipline (sources
   marked `unverified` until checked, per the epistemic-honesty rule).
3. The agent probes to locate known/edge/unknown, writes `maps/<discipline>.md`.
4. `docs/routing.md` decides the first node. Teaching begins at the edge.
